# Publish the selected story branch promptly

Apply the shared documentation evidence contract to every content edit and consistency check: inspect relevant branch-authored README/docs, design and architecture notes, changelogs, and relevant archived original story files alongside code, comments, commit messages, and tests. Include story-owned staged, unstaged, and untracked docs as appropriate; verify current claims against implementation and actual diff, attribute documented rationale, and label superseded approaches as historical. Apply the archive-accounting categories in shared.md: preserve every verified original explicit requirement, even when unimplemented, and distinguish it from speculative suggestions; never claim unsupported implementation or test passes, create repair work, blockers, or review findings. Process all `retrospective_archive.entries` independently, preserve every verified mapping in any handoff update, and exclude administrative archive changes from delivered implementation.

Read `$CODEINFO_ROOT/codeinfo_markdown/retrospective_story/shared.md` and the persisted `codeInfoStatus/flow-state/current-plan.json`; do not rely on the layout agent's reply. Verify that its `plan_path` exists, its seven-digit prefix matches the checked-out branch, and the branch contains the retrospective story number in its final segment. If identity cannot be verified, do not push or rename a branch; report the limitation and let later steps continue with any safe work.

From the repository root, use at most three reconciliation/publication attempts at this early stage. Each attempt reruns `python3 "$CODEINFO_ROOT/scripts/select_retrospective_story_number.py" --owned-plan <plan_path>` and checks live same-namespace heads immediately before push. The owned-plan option excludes only this flow's new plan from global plan collisions. If a numeric collision appears before or after push, choose the helper's number and log old → new branch/plan identity, reason, and outcome. An exact remote branch with the same branch name is not itself a numeric collision; push does not atomically reserve a number. Rename only a safe, unpublished branch proven flow-owned. If the old branch is published, leave it untouched and create a new replacement branch from current HEAD, never from develop. Do not overwrite or delete competing branches. Move only this flow-owned plan, repair internal references and current-plan, then recheck before pushing. Preserve all retrospective fields and receipts. Do not use generic handoff refresh. Never move another story's plan or branch. If safe reconciliation cannot be verified, report the collision, skip the unsafe push, and continue with other safe work. Record warnings when live remote refs are unavailable.

Before each push, perform the live collision check. Attempt `git push -u origin HEAD` before later story-section steps. After push, recheck live same-namespace numbers to catch races; if a new numeric collision exists, reconcile within the three-attempt limit. Also run `git ls-remote --heads origin refs/heads/<branch>` and verify the returned exact full ref SHA equals local `HEAD`. Report push command success separately from remote availability and exact-HEAD verification; a failed, absent, or mismatched exact-ref result is unverified publication. If all attempts are exhausted, report partial publication honestly and continue with no stale/unsafe identity. A rerun must reuse a valid corrected identity. This publishes the branch HEAD and makes its index visible to concurrent agents; uncommitted plan content remains local until the final story commit and push. Do not force-push, amend, publish unrelated local implementation as a new commit, or retry with changed credentials. A failed push is nonfatal: report the exact reason and continue the flow. Do not invoke `select_current_task.py` or create/promote task state; it would move the open final task to `__in_progress__`. Early layout invalidates only state verified to match a superseded selection; preserve it safely where owned archive evidence permits. Report an absent handoff as `not selected/documentation only`, and never claim a valid/resolved task. The later normal implementation flow performs selection. Report branch, plan, remote base, old → new identities, pushed HEAD, exact remote verification status, attempt count, and limitations.
