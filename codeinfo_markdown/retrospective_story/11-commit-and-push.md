# Commit the documented story and attempt a push

Apply the shared documentation evidence contract to every content edit and consistency check: inspect relevant branch-authored README/docs, design and architecture notes, changelogs, and relevant archived original story files alongside code, comments, commit messages, and tests. Include story-owned staged, unstaged, and untracked docs as appropriate; verify current claims against implementation and actual diff, attribute documented rationale, and label superseded approaches as historical. Apply the archive-accounting categories in shared.md: preserve every verified original explicit requirement, even when unimplemented, and distinguish it from speculative suggestions; never claim unsupported implementation or test passes, create repair work, blockers, or review findings. Process all `retrospective_archive.entries` independently, preserve every verified mapping in any handoff update, and exclude administrative archive changes from delivered implementation.

Read `$CODEINFO_ROOT/codeinfo_markdown/retrospective_story/shared.md` and the exact current-plan handoff. Follow its final publication collision protocol with at most three bounded reconciliation/publication attempts, including live numeric checks immediately before push and after push. Same-name remote presence alone is not a numeric collision. Fetch origin once, resolve latest `origin/develop`, and refresh comparison-base evidence while preserving original initial HEAD. Recheck current branch, plan status, and `git status --short`; use merge-base-to-HEAD for story delta and separate flow plan commits from implementation attribution. Repair any remaining plan-only contradiction, remove any `- **BLOCKER**` line or speculative review finding from Implementation notes, and keep only factual provenance limits in relevant story sections and task notes. Do not perform code review while preparing the story commit. If story-owned implementation remains uncommitted, name its paths and local-only status in the plan; do not claim it is in a commit or on the remote. Stage only the selected plan, independently verified archive files/deletions described below, applicable already-tracked story handoff controls when repository rules permit, and a verified tracked deletion of the prior flow-owned plan after renumbering. Never force-add ignored controls or receipts. Leave unrelated files untouched. Inspect `git diff --cached --name-status`, `git diff --cached --check`, and the staged story content. If unrelated files are already staged, preserve them and use `git commit --only -- <story paths>` so the story commit excludes them. If a safe story-only commit is unavailable, report that limitation and continue to the final reingest rather than committing unrelated work.

Recover `retrospective_archive.entries` from the current-plan handoff. Verify each mapping independently against repository evidence under the shared contract, including the allocated base or positive integer suffix destination and content hash. Include ALL verified archive destinations and relevant source deletions in this plan-only commit, alongside the selected new plan; do not assume a single source or destination. Retain earlier verified pending mappings when a source was archived repeatedly. Build one deduplicated explicit path list: include the selected plan and, after final renumbering, the prior flow-owned plan path only when it is tracked and verified deleted (never use an absent untracked pathspec); for each verified mapping include its allocated archive destination; include its source only if it is tracked and still deleted, or is now the selected new plan at a reused path; an absent untracked source is not a Git pathspec. If a different file now occupies an old source path, leave it untouched and report the evidence limit. A failed source deletion is not a completed move: preserve its per-file accounting, include any independently verified created archive, and do not stage the still-present source unless it is the selected new plan.

Before moving a replacement plan, verify its destination is unoccupied; record old → new plan paths in existing plan/state evidence. Stage explicit verified paths with `git add -A -- <story paths>`, including verified tracked deletions of the old plan and safely superseded handoffs; never use a directory-wide add. A superseded current-task or live-control deletion requires verified ownership and safe archival under shared.md; never force-add ignored state. Confirm staged paths exclude unrelated work and immutable historical review-cycle artifacts. Preserve unrelated staged files and use `git commit --only -- <story paths>` when needed. Inspect the staged diff and verify every archive's bytes against its recorded hash, including original dirty or untracked content. A reused source path is added only once as the new plan; do not attempt a separate `git rm` on it. Missing or conflicting evidence for one mapping means omit only that unsafe mapping and report the limitation; continue with all other verified mappings, not guessed files. The ignored archive receipt must remain uncommitted.

Commit story-only files with required `DEV-[Number] -` subject and four- or five-sentence body. Verify staged and committed paths exclude unrelated work and immutable historical artifacts; record commit SHA. Flow output states branch, plan, remote base, old → new identities, commit, push verification, and limitations. Do not request confirmation. After the story-only commit, publish using the bounded collision protocol. On numeric collision, rerun the selector with `--owned-plan`; leave any published branch untouched, create replacement from current HEAD, verify the replacement plan path is unoccupied, move only the flow-owned plan, record old → new paths, fix internal refs/current-plan, and invalidate only a verified obsolete current-task reference; do not invoke the selector or promote any task. Stage the new plan and the old path only if it is a verified tracked deletion; never stage an absent untracked path. Superseded tracked handoff/control deletions require verified ownership and preservation. Preserve the final task as `__to_do__` with every checkbox unchecked, report current-task as absent/not selected or an unverified preserved handoff, then commit the story-only renumber change before retrying. Never force-push, amend, delete competitors, change credentials, or stage unrelated work. After push, run `git ls-remote --heads origin refs/heads/<branch>` and require that exact full ref SHA to equal local HEAD before claiming publication success. Exact same-branch remote presence alone is not a numeric collision. Commit/push failure remains nonfatal; report honest partial status and continue final reingest.
