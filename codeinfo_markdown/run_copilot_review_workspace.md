# Run the local Copilot CLI review job

Read and follow `review_job_workspace_contract.md` first.

Use only the scheduler-assigned review job, repository, `input/`, `work/`, `output/`, and `verification/` paths prepended to this instruction. Read the pinned target and review wave from the assigned input Markdown, and read the model availability snapshot only from `input/copilot-review-spec.json`. Confirm that the repository root, current `HEAD`, `target.head_commit`, and `target.comparison_base_commit` agree before contacting any provider. Never modify source files, plans, Git state, branches, commits, remotes, another review job, or shared review handoffs.

The checked-in launcher reads `input/copilot-review-spec.json` itself. If `copilot_review_spec.available` is false, still invoke the launcher once, but it must not launch Copilot. It deterministically writes secret-free invocation, empty raw Copilot JSONL, diagnostic, not-launched status, unavailable usage, and normalized unavailable-result artifacts under this job's assigned `work/` and `output/` directories. The unavailable result preserves the model, target, and snapshotted reason as required coverage and must not fail the parent wave.

When the model is available, prepare the self-contained review-instructions file at the exact relative path `work/copilot-review-instructions.md` under the assigned job directory. It must contain the pinned story context, acceptance criteria, exclusions, exact repository, exact `<base>...<head>` range, model identity, and an explicit prohibition on source or Git modification. State explicitly that `planning/**` changes are excluded and Copilot must not inspect, read, summarize, cite, or report findings for them; the supplied story context is the authoritative replacement for reading changed planning files. Do not use conversational memory as review evidence.

Assign the exact scheduler-provided repository and job-directory paths once and set the direct command's working directory to that assigned job directory. Run the review exactly once through `$CODEINFO_ROOT/scripts/run-copilot-review.sh`; do not invoke `copilot` directly and never perform a fallback review through this wrapper agent. Pass the repository variable as `--repository`, the job-directory variable as `--workspace`, and explicit `--target-id`, `--review-wave-id`, `--job-instance-id`, `--base`, `--head`, `--model`, and `--reasoning-effort` arguments. For an external specification, also pass its snapshotted `endpointLabel` as `--endpoint-label` and pass `endpointId` as `--endpoint-id` when the snapshot contains one; never pass either option for a native specification. Do not pass, select, reconstruct, or retype individual instructions or artifact paths: the launcher derives the fixed `input/`, `work/`, and `output/` locations from the real assigned workspace and rechecks their containment before use.

The launcher owns the exact non-interactive local `/review` command, pinned range, explicit `planning/**` exclusion and Git exclusion pathspec, model, reasoning effort, Docker-contained `--allow-all` permissions, closed stdin, JSONL capture, `--no-ask-user`, `--no-auto-update`, `--no-remote`, and `--no-remote-export`. CodeInfo's Docker container is the full-access isolation boundary, matching the existing Codex and OpenCode review policy. The launcher still disables built-in GitHub MCP access and remote session export/control, protects provider credentials through secret environment handling, and confines its persisted artifacts to the assigned review workspace. The selected model API may still be an external HTTP service when the specification explicitly names an external endpoint.

Invoke the launcher with the direct `exec_command` tool, never with `functions.exec`, JavaScript, or nested `tools.exec_command`. If direct `exec_command` returns a `session_id`, retain it and poll with direct `write_stdin` until the same process returns a numeric `exit_code`. Do not relaunch the command, treat a yielded session as terminal, inspect growing files as complete, or call Copilot a second time. If continuation is genuinely lost, preserve partial artifacts and record the uncertainty honestly.

After terminal completion, reopen the invocation, raw JSONL, stderr, exit-status, usage, and normalized result artifacts. Treat stdout as JSONL with extensible event shapes rather than requiring every event to match one schema. Keep native Copilot usage separate from this wrapper agent's usage. Preserve partial output and diagnostics on non-zero exit or normalization failure.

Before returning, enumerate the files that actually exist under the assigned `output/` directory and apply the shared factual handoff contract. If the launcher's normalized output is absent, recover an honest partial, failed, or unavailable result from this job's raw artifacts without relaunching Copilot. Reopen the discovered output and do not report completion while the assigned destination is empty. Never create a remote GitHub pull-request review, publish a review, or delegate to a remote coding-agent session.
