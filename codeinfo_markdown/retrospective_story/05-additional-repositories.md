# Verify Additional Repositories

Apply the shared documentation evidence contract to every content edit and consistency check: inspect relevant branch-authored README/docs, design and architecture notes, changelogs, and relevant archived original story files alongside code, comments, commit messages, and tests. Include story-owned staged, unstaged, and untracked docs as appropriate; verify current claims against implementation and actual diff, attribute documented rationale, and label superseded approaches as historical. Apply the archive-accounting categories in shared.md: preserve every verified original explicit requirement, even when unimplemented, and distinguish it from speculative suggestions; never claim unsupported implementation or test passes, create repair work, blockers, or review findings. Process all `retrospective_archive.entries` independently, preserve every verified mapping in any handoff update, and exclude administrative archive changes from delivered implementation.

Read `$CODEINFO_ROOT/codeinfo_markdown/retrospective_story/shared.md` and the selected plan's `### Additional Repositories`. Inspect the work's concrete repository scope. List a repository only when the documented story actually changed it or requires it as an explicit implementation owner. Verify each listed path exists and is a Git repository, and read its `AGENTS.md` before making changes there. Do not infer a repository path from a similar name. Use `- No Additional Repositories` when appropriate. Update `additional_repositories` in the current-plan handoff to match the section, keeping the comparison base and initial HEAD fields intact. For each changed additional repository, preserve its own original initial HEAD, freshly fetch and resolve `origin/develop` for its comparison-base tip (or record null and the fetch/ref limitation), and use merge-base-to-initial-HEAD for its story delta per shared.md. Keep source attribution separate from review base and retain all handoff metadata. Recheck every repository's branch and story number before proceeding; omit an unverifiable repository identity from mutations while continuing with verified scope.
