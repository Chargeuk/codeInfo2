# Establish the branch snapshot and create the initial story

Read `$CODEINFO_ROOT/codeinfo_markdown/retrospective_story/shared.md` first. The native reingest step has already run. Confirm the working repository and use fresh Git reads: `git status --short --branch`, `git branch --show-current`, `git log -1 --format=%H`, `git remote -v`, branch tracking/provenance, and relevant refs. Establish an explicit comparison base for work already done. Prefer recorded branch provenance or a clearly supported merge base against the source branch. Never treat the branch's upstream tracking ref as the source branch merely because it is configured. If multiple plausible bases produce materially different diffs and repository evidence does not resolve them, stop and ask for the missing base. Inspect `git diff --stat <base> <initial-head>`, `git diff --name-status <base> <initial-head>`, `git diff --cached`, `git diff`, and untracked file names. Exclude unrelated files by evidence, not a blanket filename guess. Stop if any story-owned implementation work is still uncommitted, because the later plan push would omit it. Do not stage or commit implementation files.

Read existing plan filenames and branch conventions to select a collision-free seven-digit story number. Reuse the branch's story number when it is unambiguous and available; otherwise choose the next available number. Follow the target repository's branch instructions, creating a matching feature branch from the current checkout if required without discarding changes. Do not switch to a branch that would overwrite local work. Read the no-tasks template using the lookup order in `$CODEINFO_ROOT/codeinfo_markdown/retrospective_story/shared.md` and create `planning/<number>-<slug>.md` with its full initial heading layout and concise factual starter content. Keep the title user-facing and based on observed behavior. Do not add `# Tasks` yet.

Write `codeInfoStatus/flow-state/current-plan.json` with the exact relative `plan_path`, `comparison_base_commit`, `initial_head_commit`, and `additional_repositories: []`. Include `branched_from` only when this step actually creates the feature branch and its source is known. A prior current-plan handoff may identify another story: this new-story flow may replace that transient handoff after reporting the old path and creating the new plan. Never edit the old plan merely because it was previously selected. Ensure the handoff path is ignored or otherwise handled according to repository rules. Report the branch, base SHA, initial HEAD SHA, plan path, and evidence limitations. Stop if any identity cannot be established safely.
