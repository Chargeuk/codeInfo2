# Archive the current branch's original stories

Read the target repository's `AGENTS.md` and `$CODEINFO_ROOT/codeinfo_markdown/retrospective_story/shared.md`. This is the FIRST step, before working reingest. From the verified target repository root run `python3 "$CODEINFO_ROOT/scripts/archive_retrospective_story.py"` once. The helper uses the fresh current branch and the numeric branch/story convention in `flow_state_utils.py`, never an old current-plan handoff. It discovers current top-level numbered planning files afresh on every invocation and moves every verified numeric match in deterministic filename order. Multiple matching files are all in scope; they are not an ambiguous identity.

Allocate `planning/one-shot/one-shot-<original-stem>.md`, then `one-shot-<original-stem>-1.md`, `-2.md`, and so on before the extension. Exclusive destination creation retries occupied names and allocation races without overwriting or skipping a matching file. Create the archive directory only when needed. Preserve tracked, dirty, and untracked working bytes without force. A present replacement source is archived too, using the next free suffix; a prior receipt never suppresses a present source. Existing archives are never moved or modified.

No matching story is a normal no-op. Detached or unnumbered branches and unsafe paths are safe no-ops with reasons; do not guess identities. Per-file archive errors are nonfatal: report each result, continue every remaining verified match, and let the flow continue with honest partial accounting. Do not repair implementation, stage, commit, push, or prefix archived filenames twice. Do not select the archived one-shot filename as the current plan: it does not meet the numbered-plan requirement.

If no sources remain, recover verified prior entries for a stable retry without moving archives. Receipt limitations must not suppress freshly discovered sources. If receipt recovery is unavailable, report that evidence limit and continue safe work without inventing archive ownership.

Relevant branch-authored documentation, including every relevant archived original story file, is evidence under the shared contract. Read only bounded relevant sections as needed; do not turn proposals or template text into delivered scope or additional work.
