# Publish the selected story branch promptly

Apply the shared documentation evidence contract to every content edit and consistency check: inspect relevant branch-authored README/docs, design and architecture notes, changelogs, and relevant archived original story files alongside code, comments, commit messages, and tests. Include story-owned staged, unstaged, and untracked docs as appropriate; verify current claims against implementation and actual diff, attribute documented rationale, and label superseded approaches as historical. Unsupported proposals or conflicting claims are evidence limits, never extra tasks, blockers, review findings, or proof of test passes. Process all `retrospective_archive.entries` independently, preserve every verified mapping in any handoff update, and exclude administrative archive changes from delivered implementation.

Read `$CODEINFO_ROOT/codeinfo_markdown/retrospective_story/shared.md` and the persisted `codeInfoStatus/flow-state/current-plan.json`; do not rely on the layout agent's reply. Verify that its `plan_path` exists, its seven-digit prefix matches the checked-out branch, and the branch contains the retrospective story number in its final segment. If identity cannot be verified, do not push or rename a branch; report the limitation and let later steps continue with any safe work.

From the target repository root, rerun `python3 "$CODEINFO_ROOT/scripts/select_retrospective_story_number.py" --owned-plan <plan_path>` to check live same-namespace remote heads immediately before publishing. The owned-plan option excludes only this flow's new plan from global plan collisions. If the helper proposes a different number because a competing plan or same-namespace branch appeared, choose its new number. Rename only a branch newly created by this flow and still unpublished; if the selected branch predates this flow or is published, create a new branch with the new number from the checked-out HEAD instead of renaming or rewriting it. Move only this flow's new plan, update its story-number references and current-plan handoff, then recheck before pushing. Never move another story's plan or branch. If safe reconciliation cannot be verified, report the collision, skip the unsafe push, and continue with other safe work. Record warnings when live remote refs are unavailable.

Attempt `git push -u origin HEAD` immediately after verification or safe reconciliation, before any later story-section step. This publishes the branch HEAD and makes its index visible to concurrent agents; uncommitted plan content remains local until the final story commit and push. Do not force-push, amend, publish unrelated local implementation as a new commit, or retry with changed credentials. A failed push is nonfatal: report the exact reason and continue the flow. After a successful push, check live same-namespace heads again; if a competing numbered branch appeared, report that collision rather than claiming the index is uniquely reserved. The push narrows the race window but does not make allocation atomic across distinct branch names. Report the current branch, plan path, pushed HEAD when successful, remote verification status, and any remaining collision or local-only evidence.
