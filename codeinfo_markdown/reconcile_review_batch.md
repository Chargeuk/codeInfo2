# Reconcile the current review batch

Read and follow `$CODEINFO_ROOT/codeinfo_markdown/shared/review-artifact-handoff.md`; reconciliation is always an applicable artifact for a resolved batch.

This is an autonomous flow execution step, not a planning interview. The required outcome and boundaries are already decided. Do not ask the user questions, offer choices, wait for confirmation, or finish with a question. Resolve uncertainty from the immutable batch evidence, make the best safe judgement available, and record uncertainty in the artifact.

Read `codeInfoStatus/flow-state/current-plan.json` only to identify the exact padded story identifier. Set `batch_handoff` to `codeInfoTmp/reviews/<exact-story-id>-current-review-batch.md`, then set `batch_dir` exactly once by running `batch_dir="$(python3 "$CODEINFO_ROOT/scripts/check_review_workspace.py" resolve --batch-handoff "$batch_handoff")"`. Reuse those exact variables throughout this invocation; never retype, reconstruct, or switch to a similar-looking batch path. Inspect every job directory discovered directly below `$batch_dir/jobs/`. Do not use provider names, an expected reviewer count, another pointer file, or a required result schema to decide what exists.

Understand each self-describing output and verification report. Reconcile supported findings, duplicates, severity disagreements, target ownership, exclusions, unavailable work, and residual uncertainty. Preserve useful sibling findings when another job is partial or unavailable.

For every finding or rejected candidate, preserve every generating or corroborating job that can be established from `job.md`, launch evidence, native work, output, and verification. Record the human-readable review name when present, flow name, exact job instance identity, and target or repository alias. Do not reduce several supporting jobs to one convenient source and do not leave later disposition agents to decode an opaque job ID as the complete harness list. Discover provenance from the jobs that exist; never hard-code providers, reviewer counts, or scheduling groups.

Also inventory every direct job exactly once, including jobs with no finding or unavailable coverage. Preserve its human-readable name, flow, job identity, target, and honest outcome. When optional `work/review-usage/` evidence exists, carry input, cached input, and output separately. For multi-stage jobs, total each category only when every designated artifact reports it; otherwise retain the known partial sum as `At least <number> reported; incomplete`, or `Not reported` when no value exists. Never add cached input to input, count administrative work, or let usage affect findings or outcome.

Always write a clear batch reconciliation under the batch's `reconciliation/` directory. When complete reconciliation is impossible, still write an honest partial or unavailable reconciliation that explains what was inspected, what remains unknown, and why; never substitute clarification questions for the artifact. Include enough provenance for later disposition agents to reopen the original job evidence. Copy the batch identity and paths from the authoritative current-batch handoff or `batch-launch.md` rather than reconstructing them. Do not edit the story plan or implementation in this step.

Run `python3 "$CODEINFO_ROOT/scripts/check_review_workspace.py" check --batch-handoff "$batch_handoff"` as a factual preflight. `CODEINFO_ROOT` is the workflow harness root, not the target repository. Repair only this step's derived reconciliation artifact. Treat missing or inconsistent scheduler-owned launch, input, job-directory, or `job.md` evidence as an honest coverage limitation rather than recreating it, and continue with whatever trustworthy job evidence is available.

Before returning, reopen the written reconciliation, confirm that it is non-empty, refers to the exact authoritative batch, accounts for every discovered job, and states a completed, partial, or unavailable result in ordinary prose. Return a concise execution summary and artifact path, not questions.
