# Verify Description

Apply the shared documentation evidence contract to every content edit and consistency check: inspect relevant branch-authored README/docs, design and architecture notes, changelogs, and relevant archived original story files alongside code, comments, commit messages, and tests. Include story-owned staged, unstaged, and untracked docs as appropriate; verify current claims against implementation and actual diff, attribute documented rationale, and label superseded approaches as historical. Unsupported proposals or conflicting claims are evidence limits, never extra tasks, blockers, review findings, or proof of test passes. Process all `retrospective_archive.entries` independently, preserve every verified mapping in any handoff update, and exclude administrative archive changes from delivered implementation.

Read `$CODEINFO_ROOT/codeinfo_markdown/retrospective_story/shared.md`, `### Description`, and `## Implementation Ideas` in the selected plan. Inspect the supported base-to-initial-HEAD diff when a base exists, current source and tests, added or modified comments, and relevant implementation commit subjects and bodies. Use comments and commit messages to understand the reported why, then verify the delivered what against code and tests. Rewrite Description in plain language to explain the prior state, observed completed behavior, and why it matters. For internal-only work, describe the evidenced performance, stability, or maintenance result without claiming a new user interaction or interface change. State that this retrospective story records the behavior already implemented on the branch and does not request additional product behavior. Distinguish direct evidence from inference. Do not claim an outcome merely because a file or test name suggests it.

Fill `## Implementation Ideas` as a brief past-tense map of components, contracts, migrations, and tests actually changed, with repository-relative references. Remove speculative proposals and template examples. Check both sections against observed branch evidence; later tasking will provide the detailed implementation record.
