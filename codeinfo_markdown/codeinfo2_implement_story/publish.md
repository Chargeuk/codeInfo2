# Commit valid owned work and publish only through verified procedures

Read `$CODEINFO_ROOT/codeinfo_markdown/codeinfo2_implement_story/shared.md` and fresh target `AGENTS.md` guidance.

The continuing main owns authorized parent commits and pushes. Discover documented commit, remote, push, and pull-request procedures and available authorized tools. A missing remote, unknown base, credentials, permission, or unreachable host means report unavailable and continue independent local work. Never guess endpoints, force-push, rewrite history, or claim unverified publication. A safe local commit may proceed independently of remote availability; do not publish another owner's work.

Before acting, verify the selected target, exact branch, ownership, pre-existing commits, index/worktree, merge state, and current proof/review status. Compare the owned diff and index with existing local commits and any safely verified remote ref. Do not use blanket staging. Stage only explicit paths verified as owned and authorized; preserve unrelated staged/worktree content and protected plan, current-plan handoff, and story-progress content even if an incoming clean merge would replace it. Never commit unresolved conflicts, unowned paths, secrets, or another worker's active/uncertain work. If the intended content is already committed, retain it; do not create an empty or duplicate commit. If nothing is safely committable, report a no-op with reason.

Before a push, verify the exact selected local branch and remote ref using the documented procedure. If they match, retain the verified state without pushing. Otherwise push only that branch with one explicit refspec, bounded attempts, and no force, plus, mirror, all-branch, or tag push. After an ambiguous outcome, read the actual remote ref before deciding whether a retry is safe. Do not repeat an unchanged unavailable operation. If remote state is unavailable or advanced unexpectedly, preserve local commits and report the limitation without rewriting history.

Keep local commit/no-op/failure separate from push, pull request, checks, and review outcomes. Run only checks authorized and required by the selected contract and repository procedure; never make excluded testing a push gate or claim an unrun check passed. External review unavailable is not a pass; due local review remains due. Report exact committed files/ref and verified remote result, omitted work, and blockers.
