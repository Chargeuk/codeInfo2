# Record one review batch

Use the immutable batch launch, verified disposition, existing repair evidence, current Git state for each target repository, and the bounded assigned plan. Follow the shared artifact recovery and repository ownership rules. Recover understandable evidence, but never invent a fix, commit, test result, candidate, or clean outcome.

Always write the batch OUTCOME to its existing evidence path, including every disposition survivor and its verified, open, or unavailable status. Preserve the immutable batch ID and stable finding identities; record repositories and candidate heads, changed files, exact fix commits when known, affected findings, test commands/results, exclusions, and proof limitations when available. Include focused evidence for verified fixes and the precise open reason for every unresolved or unavailable finding.

Create or update a plan TASK only when the evidence proves one or more fixes. It records only that verified subset: every subtask is checked, and no open finding checkbox is included. Follow `$CODEINFO_ROOT/codeinfo_markdown/shared/completed-review-fix-task.md` for the exact batch identity, title, `Created` value/placement, and `completed_review_fixes` role; scope the task to this local batch. Do not inherit that document's complete-pass settlement behavior or ordering, create a replacement validation task, or defer open findings to another task. If zero fixes are verified, create no plan task. Confirm the outcome and any created or updated task, respect the caller's commit boundary, and stop.
