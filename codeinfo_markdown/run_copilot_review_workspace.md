# Run the local Copilot CLI review job

Read and follow `review_job_workspace_contract.md` first.

Use only the scheduler-assigned review job, repository, `input/`, `work/`, `output/`, and `verification/` paths prepended to this instruction. Read the pinned target and review wave from the assigned input Markdown, and read the model availability snapshot only from `input/copilot-review-spec.json`. Confirm that the repository root, current `HEAD`, `target.head_commit`, and `target.comparison_base_commit` agree before contacting any provider. Never modify source files, plans, Git state, branches, commits, remotes, another review job, or shared review handoffs.

If `copilot_review_spec.available` is false, do not launch Copilot. Write secret-free invocation, empty raw JSONL, diagnostic, not-launched status, unavailable usage, and normalized unavailable-result artifacts under this job's assigned `work/` and `output/` directories. Preserve `endpointLabel`, `modelId`, `reasoningEffort`, target, base, head, and the snapshotted `unavailableReason`, but never write an endpoint credential, key map, authorization value, or secret-bearing URL. This unavailable result is required coverage and must not fail the parent wave.

When the model is available, prepare a self-contained review-instructions file under the assigned `work/` directory. It must contain the pinned story context, acceptance criteria, exclusions, exact repository, exact `<base>...<head>` range, model identity, and an explicit prohibition on source or Git modification. Do not use conversational memory as review evidence.

Run the review exactly once through `$CODEINFO_ROOT/scripts/run-copilot-review.sh`; do not invoke `copilot` directly and never perform a fallback review through this wrapper agent. Pass the exact repository root as `--repository` and the exact assigned `review_job.job_dir` as `--workspace`; never substitute the repository root for the workspace. Pass explicit `--target-id`, `--review-wave-id`, `--job-instance-id`, `--base`, `--head`, `--model`, `--reasoning-effort`, `--instructions`, `--stdout`, `--stderr`, `--status`, `--invocation`, `--normalized`, and `--usage` arguments. Pass `--endpoint-label` only for an external specification. Put raw Copilot JSONL, raw stderr, exit status, secret-free invocation metadata, and native Copilot usage under the assigned `work/` directory, and put the normalized review result under the assigned `output/` directory.

The launcher owns the exact non-interactive local `/review` command, pinned range, model, reasoning effort, read-only permissions, closed stdin, JSONL capture, `--no-ask-user`, `--no-auto-update`, `--no-remote`, and `--no-remote-export`. It disables built-in GitHub MCP access and remote session export/control. The selected model API may still be an external HTTP service when the specification explicitly names an external endpoint.

Invoke the launcher with the direct `exec_command` tool, never with `functions.exec`, JavaScript, or nested `tools.exec_command`. If direct `exec_command` returns a `session_id`, retain it and poll with direct `write_stdin` until the same process returns a numeric `exit_code`. Do not relaunch the command, treat a yielded session as terminal, inspect growing files as complete, or call Copilot a second time. If continuation is genuinely lost, preserve partial artifacts and record the uncertainty honestly.

After terminal completion, reopen the invocation, raw JSONL, stderr, exit-status, usage, and normalized result artifacts. Treat stdout as JSONL with extensible event shapes rather than requiring every event to match one schema. Keep native Copilot usage separate from this wrapper agent's usage. Preserve partial output and diagnostics on non-zero exit or normalization failure.

Before returning, enumerate the files that actually exist under the assigned `output/` directory and apply the shared factual handoff contract. If the launcher's normalized output is absent, recover an honest partial, failed, or unavailable result from this job's raw artifacts without relaunching Copilot. Reopen the discovered output and do not report completion while the assigned destination is empty. Never create a remote GitHub pull-request review, publish a review, or delegate to a remote coding-agent session.
