# Commit the documented story and attempt a push

Read `$CODEINFO_ROOT/codeinfo_markdown/retrospective_story/shared.md` and the exact current-plan handoff. Recheck the current branch, recorded comparison base and initial HEAD, plan status, and `git status --short`. Require the audited plan to have completed implementation tasks and exactly one open final validation task. If any story-owned implementation remains uncommitted, stop and report the paths; do not push a plan that claims its implementation is already committed. Stage only the selected plan file and any explicitly created companion story document; leave unrelated files untouched. Inspect `git diff --cached --name-status`, `git diff --cached --check`, and the staged content. If the index already contains unrelated staged files, stop and report them instead of silently committing them or resetting the user's index.

Commit the story files with the repository's required `DEV-[Number] -` subject and a four- or five-sentence body explaining the retrospective plan, completed implementation record, open final validation task, and why it is deferred. Verify the commit contains only intended story files and record the commit SHA. Attempt `git push -u origin HEAD` for the current branch. A push failure is nonfatal: report the exact failure succinctly, leave the local commit intact, and finish this step successfully so the final reingest still runs. Do not amend, force-push, retry with changed credentials, or stage unrelated work merely to make the push pass.
