# Verify Additional Repositories

Apply the shared documentation evidence contract to every content edit and consistency check: inspect relevant branch-authored README/docs, design and architecture notes, changelogs, and relevant archived original story files alongside code, comments, commit messages, and tests. Include story-owned staged, unstaged, and untracked docs as appropriate; verify current claims against implementation and actual diff, attribute documented rationale, and label superseded approaches as historical. Apply the archive-accounting categories in shared.md: preserve every verified original explicit requirement, even when unimplemented, and distinguish it from speculative suggestions; never claim unsupported implementation or test passes, create repair work, blockers, or review findings. Process all `retrospective_archive.entries` independently, preserve every verified mapping in any handoff update, and exclude administrative archive changes from delivered implementation.

Read `$CODEINFO_ROOT/codeinfo_markdown/retrospective_story/shared.md`, the selected plan's `## Additional Repositories` or `### Additional Repositories` section, and the current-plan handoff. Reconcile approved entries and metadata from the selected same-story plan, handoff, and trustworthy same-story archive evidence; do not infer scope from another story or incidental plan storage location. Preserve known approved entries if temporarily unreadable, report affected operations unavailable, and use `- No Additional Repositories` / `[]` only when no additional scope was approved. Do not require redundant approval for repositories already included in the selected plan. Verify each approved path independently as a Git repository and read its `AGENTS.md` before changes there; an unverifiable entry affects only that repository. Update the plan section and handoff together while retaining approved entries and provenance. For each repository independently, preserve any already-proven original `initial_head_commit` and source provenance through reruns; capture its HEAD or source provenance only when not already established. Identify its configured remote and verify the remote default branch from fresh Git remote HEAD/ref evidence, fetch that remote once, and resolve its default-branch comparison SHA (or record null and the precise fetch/ref limitation). Use merge-base-to-initial-HEAD for that repository's story delta, keeping source attribution separate from the comparison default. Continue with other repositories after a per-repository failure and preserve all handoff metadata.
