# Identify previously accepted review findings

Read and follow `$CODEINFO_ROOT/codeinfo_markdown/shared/review-artifact-handoff.md` and `$CODEINFO_ROOT/codeinfo_markdown/shared/repeated-review-repair.md`. This step only routes the current accepted findings; do not implement changes, invent new findings, reconsider earlier gate removals, or ask a human.

Use the scheduler-assigned batch directory and plan. Only when no scheduler assignment exists, resolve the exact immutable current batch from the canonical current-batch handoff. Read its disposition, combined filtering audit, target snapshot, and accepted finding evidence. If trustworthy current-batch evidence confirms an empty accepted actionable set, record that in `repeated-findings.md` and return without querying history. Otherwise, from the target repository root, run:

```bash
python3 "$CODEINFO_ROOT/scripts/review_findings.py" list --exclude-batch '<exact current batch ID>'
```

The helper resolves the active plan through the current-plan handoff; use `--plan` only with an established explicit plan path. Read the compact historical records: review identity, repository, Finding ID, title, Simple description, and expansion reference. A historical-match candidate needs positive accepted provenance, demonstrated either by the helper's explicit accepted metadata or by recovering its exact `Accepted` source section through bounded reads. Missing metadata alone is an evidence limitation, not a rejection. Rejected or ignored records never qualify; a legacy-unclassified record remains non-eligible until its actual `Accepted` source section establishes positive provenance. A separate demonstrably Accepted historical record for the same behavior can qualify independently. These are previously seen issues, not proof of successful fixes. Missing descriptions or legacy sections produce coverage limitations and bounded source ranges; inspect relevant ranges through the plan helpers or bounded reads before concluding there is no match. Do not silently drop older records. A partial index cannot support a clean history conclusion, but it does not by itself create eligible Astra work.

Compare each current accepted actionable finding with positively accepted historical descriptions. Match the underlying trigger, violated behavior, and affected contract, not just the filename, wording, severity, or subsystem. Different IDs can represent the same issue. The same ID in another review or repository does not establish a match. For a plausible accepted-history match, make bounded checks of the linked repair evidence: an attempted repair must be tied to this same finding and underlying behavior through a concrete commit/diff, implementation record, or equivalent finding-specific proof. A matching review task, batch, or same Finding ID by itself is not an attempted repair. Rejected or ignored history never qualifies; legacy-unclassified history needs recovery of an actual Accepted source section before it can qualify. Do not infer an attempt from missing evidence. Repository identity is evidence to inspect, never a guessed authority to edit.

Expand plausible matches only as needed:

```bash
python3 "$CODEINFO_ROOT/scripts/review_findings.py" expand --reference '<exact reference from list>'
```

Keep costs small: start with descriptions, expand plausible candidates, and leave root-cause investigation to Astra. Route a current finding to Astra research only when both a plausible historical Accepted match and trustworthy evidence of an attempted repair for that same behavior exist. Route no-match, rejected/ignored/legacy-only history, and matching uncertainty to ordinary repair when its current authorization and materiality support independent repair. A missing or unavailable index requires bounded recovery; do not invoke Astra for uncertainty alone. Preserve a current finding that cannot safely enter ordinary repair as an explicit unavailable routing limitation for complete-pass settlement, while clearly classified siblings proceed normally.

Write one self-describing `repeated-findings.md` under this batch's reconciliation directory. State batch identity, purpose, evidence/coverage, each current finding and owning target, its route and reason, and every candidate's exact historical review identity, Finding ID, accepted provenance, repository information, expansion reference, and attempted-repair evidence or its absence. Explicitly account for all current accepted findings, including a trustworthy empty accepted set and no eligible candidates. Do not copy the entire plan or create a permanent issue ledger. Reopen the artifact and confirm the handoff as required by the shared contract; research will append its outcomes to this same artifact.
