# Verify Additional Repositories

Apply the shared documentation evidence contract to every content edit and consistency check: inspect relevant branch-authored README/docs, design and architecture notes, changelogs, and relevant archived original story files alongside code, comments, commit messages, and tests. Include story-owned staged, unstaged, and untracked docs as appropriate; verify current claims against implementation and actual diff, attribute documented rationale, and label superseded approaches as historical. Apply the archive-accounting categories in shared.md: preserve every verified original explicit requirement, even when unimplemented, and distinguish it from speculative suggestions; never claim unsupported implementation or test passes, create repair work, blockers, or review findings. Process all `retrospective_archive.entries` independently, preserve every verified mapping in any handoff update, and exclude administrative archive changes from delivered implementation.

Read `$CODEINFO_ROOT/codeinfo_markdown/retrospective_story/shared.md`, the selected plan's `## Additional Repositories` or `### Additional Repositories` section, and the current-plan handoff. The plan section is authoritative: an absent section or explicit `- No Additional Repositories` means `[]` in the derived handoff. Preserve proven provenance and valid metadata only for repositories still listed; do not revive removed or stale scope from the handoff or archive. Carry applicable original scope into the active plan as normal content/accounting before deriving the handoff. Reflect explicit user scope changes minimally in that section before claiming the handoff represents them; this is ordinary plan maintenance, not an approval gate. If the plan save is unavailable, report the dependent handoff update as unsaved or partial and continue safe independent work. Do not require renewed approval for repositories approved in the plan. Verify each listed path independently as a Git repository and read its `AGENTS.md` before changes there; an unverifiable entry affects only that repository. For each repository independently, preserve proven original `initial_head_commit` and source provenance through reruns; capture its HEAD or source provenance only when not already established. Identify its configured remote and verify the remote default branch from fresh Git remote HEAD/ref evidence, fetch that remote once, and resolve its default-branch comparison SHA (or record null and the precise fetch/ref limitation). Use merge-base-to-initial-HEAD for that repository's story delta, keeping source attribution separate from the comparison default. Continue with other repositories after a per-repository failure and preserve applicable handoff metadata.
