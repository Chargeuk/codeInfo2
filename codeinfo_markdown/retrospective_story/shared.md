# Retrospective story contract

This flow documents implementation that already exists. Read the target repository's `AGENTS.md` and `codeinfo_markdown/repository_information.md` when present. Use `code_info` first for repository facts, then inspect Git and source files directly. Treat indexed content as navigation help; Git and current disk contents establish the actual work.

Read `codeInfoStatus/flow-state/current-plan.json` to identify the exact `plan_path`, `comparison_base_commit`, `initial_head_commit`, and additional repository scope. Reopen that plan from disk on every step. Do not select another plan or infer a missing comparison base. Compare the base to the initial HEAD and separately inspect staged, unstaged, and untracked work; exclude the newly generated plan from implementation evidence. If HEAD or the relevant source changes drift during the flow, stop and report it instead of silently documenting a different snapshot.

The implementation being documented must be committed before this flow publishes a plan. Inspect dirty work to identify its relationship to the story. If any story-owned implementation file is staged, unstaged, or untracked, stop and report the affected paths rather than pushing a completed-task plan while its implementation remains only on disk. Unrelated dirty files remain untouched.

Read only the bounded sections of a large plan using `$CODEINFO_ROOT/scripts/plan_sections.py` or focused `rg` and `sed` reads. Do not write secrets or machine-specific paths outside the plan's `Additional Repositories` entries. Keep the plan's user-facing scope tied to observed branch changes and explicit user instructions; do not invent intent, outcomes, test passes, or commits. A source change is evidence of implementation, not evidence that an automated or manual test passed.

The planning template lookup is: current working repository's `planning/plan_format_no_tasks.md`, then `codeInfo2` through `code_info`, then another indexed repository. The task template follows the same order for `planning/plan_format.md`. If no template can be found, use the headings established by the current repository's existing plans and report the fallback.

The final task is deliberately open. Follow `$CODEINFO_ROOT/codeinfo_markdown/shared/final-task-creation.md` for its shape and repository-supported commands. Do not run or check off its build, suite, lint, formatting, or manual guidance in this documentation flow. Earlier implementation tasks may be `__done__` when their work is demonstrated by Git and source evidence. Mark an earlier testing checkbox complete only with evidence of that exact test execution; otherwise put the missing full regression check in the open final task and explain the historical evidence limit in Implementation notes.
