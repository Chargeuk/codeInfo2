# Commit the documented story and attempt a push

Read `$CODEINFO_ROOT/codeinfo_markdown/retrospective_story/shared.md` and the exact current-plan handoff. Recheck the current branch, supported comparison base and initial HEAD, plan status, and `git status --short`. Repair any remaining plan-only contradiction and keep unresolved evidence in `### Questions` and relevant Implementation notes. If story-owned implementation remains uncommitted, name its paths and local-only status in the plan; do not claim it is in a commit or on the remote. Stage only the selected plan file and any explicitly created companion story document; leave unrelated files untouched. Inspect `git diff --cached --name-status`, `git diff --cached --check`, and the staged story content. If unrelated files are already staged, preserve them and use `git commit --only -- <story paths>` so the story commit excludes them. If a safe story-only commit is unavailable, report that limitation and continue to the final reingest rather than committing unrelated work.

Commit the story files with the repository's required `DEV-[Number] -` subject and a four- or five-sentence body explaining the retrospective plan, documented implementation, open final validation task, and any material evidence limit. Verify the commit contains only intended story files and record the commit SHA. After a successful story commit, attempt `git push -u origin HEAD` for the current branch. A commit or push failure is nonfatal for this documentation flow: report the exact failure succinctly and finish this step successfully so the final reingest still runs. Do not amend, force-push, retry with changed credentials, or stage unrelated work merely to make the push pass.
