# Merge the verified target base branch when safely available

Read `$CODEINFO_ROOT/codeinfo_markdown/codeinfo2_implement_story/shared.md` and apply it. This stage runs at the existing base-integration points; it does not create a new fetch prerequisite.

Stage goal: integrate the target repository’s verified base source only when it is available, not already included, and the merge is safely owned. Inspect the selected branch/scope, dirty and staged work, merge state, remote configuration, documented repository procedure, and available source ancestry. Continuing main owns only its valid integration merge commit; the coder owns conflict repairs and the tester owns authorized checks. Compare against existing commits, verify resulting parents/tree and ownership, then report retained/merged state and invalidated evidence.

Resolve the fresh selected handoff, branch/scope, Git ownership, and target repository instructions first. Capture HEAD, index/worktree state, unrelated changes, and any existing merge state. Do not switch branches, rebase, or touch another owner’s merge. Discover the actual remote and base ref from verified Git configuration and repository instructions; never assume a host, remote name, or branch name.

If a supported, authorized remote fetch is available and useful, make one bounded attempt with a bounded network timeout; allow one bounded retry only for a transient fetch failure, then verify the fetched identity/hash. Remote access is not a prerequisite. On unavailable/failed fetch, do not repeatedly probe unchanged conditions: use a safely verified cached ref, then a verified local base ref if useful. Clearly report which source was used and whether it may be stale. If no safe source exists, retain valid local work and report integration unavailable while continuing later local work.

If the selected source is already an ancestor of current HEAD, retain state and make no duplicate merge commit. Otherwise, merge it into the current verified story branch using `--no-commit --no-ff` so the merge remains inspectable before finalization. Delegate every conflict resolution and code/config/test/file edit to `coding_agent`; delegate required checks and substantive documentation to `automated_testing_agent`, subject to user scope. Wait for repairs and authorized checks before finalizing; unavailable remote state alone does not make local work fail.

Before finalizing, inspect the complete proposed merge index/tree against captured pre-merge HEAD/state and the verified source. Preserve unrelated staged/worktree changes and protected plan, handoff, and progress content even if an incoming clean version would replace it. Do not stage unrelated paths or commit another owner’s work. Use a Git-supported full merge commit, never a path-only merge commit; follow the target’s documented commit convention when verified, otherwise use a concise descriptive subject. Verify resulting parents/source/tree, preservation of unrelated state, and absence of MERGE_HEAD/unmerged entries. An up-to-date no-op needs no commit. Do not push in this stage.

If a merge cannot be safely finalized, abort only this invocation’s own pending merge when pre-merge baseline and ownership are verified and an abort preserves that baseline. Never use forced checkout, discard, reset, clean, stash, guessed targets, or touch another owner’s merge. If safe restoration cannot be established, preserve the actual state and report only the unsafe operations blocked; continue independent safe work. Do not leave an invocation-owned pending merge that can safely be aborted to block later work.

Report actual fresh/cached/local source, completed integration or no-op/unavailable/restored state, authorized check outcome, changed paths, and limitations. Remote failure is nonfatal, is not proof, and does not prevent local commits or later stages. This prompt applies at the existing initial, pre-conversion, and post-retrospective base-integration stages.
