# Audit the retrospective story

Apply the shared documentation evidence contract to every content edit and consistency check: inspect relevant branch-authored README/docs, design and architecture notes, changelogs, and relevant archived original story files alongside code, comments, commit messages, and tests. Include story-owned staged, unstaged, and untracked docs as appropriate; verify current claims against implementation and actual diff, attribute documented rationale, and label superseded approaches as historical. Unsupported proposals or conflicting claims are evidence limits, never extra tasks, blockers, review findings, or proof of test passes. Process all `retrospective_archive.entries` independently, preserve every verified mapping in any handoff update, and exclude administrative archive changes from delivered implementation.

Read `$CODEINFO_ROOT/codeinfo_markdown/retrospective_story/shared.md`, the selected plan handoff, fresh Git state, and bounded plan sections. This audits the document's factual coverage and structure only; it does not review code quality or test adequacy. Run `python3 "$CODEINFO_ROOT/scripts/plan_status.py" --plan <plan_path> --include-tasks` and `python3 "$CODEINFO_ROOT/scripts/story_workflow_status.py"`. Compare every story-owned changed file and implemented behavior from the supported Git range when available, plus relevant working-tree changes, against an implementation task. Recheck changed comments and relevant implementation commit subjects and bodies against the factual rationale recorded in each section and Implementation notes. Check the top-level Description, Acceptance Criteria, and Out Of Scope contract against observed branch evidence; reject any added user-facing or interface behavior beyond the implementation, including invented visible behavior for internal-only work; ensure Out Of Scope gives story-specific conceptual boundaries for each delivered behavior, not just generic exclusions or file lists. Remove any inferred future behavior or unrelated repair work. Check that no completed Testing item lacks actual successful execution evidence. Repair documentation omissions directly in the plan while keeping Implementation notes focused on implemented work and verified historical execution.

Confirm `### Acceptance Criteria` contains appropriate automated test coverage for delivered behavior and all three standing code-quality requirements, even if their wording varies: no unused newly added code; accurate high-level comments on substantive changes explaining what and why; and no pre-existing variables or parameters made unused by the branch changes. Restore missing criteria, but do not inspect code or tests to judge whether those criteria pass. Remove every `- **BLOCKER**` line or speculative review finding from Implementation notes; retain factual implementation and historical execution records. Remove any Questions section copied from a template. Confirm Acceptance Criteria and Out Of Scope exclude further user-facing or interface changes and state an internal-only outcome without inventing visible behavior when applicable. Preserve the distinction between observed implementation and future acceptance validation; continue to the commit attempt with only factual provenance limits visible.

Verify exactly one final task exists, is `__to_do__`, and has only lint/format checkbox types in Subtasks; its Testing must cover full build, applicable startup/shutdown, all relevant full suites, and supported lint/format. Manual Testing Guidance must remain checkbox-free and request screenshots only when useful; internal-only work may have no applicable manual scenario. Repair the plan so the final task is the only open task and has no checked items, using honest notes for incomplete evidence. Check plan whitespace, including newly created untracked plans, using read-only inspection; and report the plan path, counts, and remaining final validation work. Do not commit or push here.
