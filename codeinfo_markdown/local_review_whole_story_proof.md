# Local whole-story proof workflow

Run this as one proof invocation against the verified current repository candidate. Follow the canonical story plan, repository guidance, shared final-task contract, and current source. Keep all results tied to the actual candidate, including relevant staged, unstaged, and untracked changes as well as `HEAD`. The caller owns branch and commit boundaries: do not switch branches, stage, commit, or push. Do not claim proof unsupported by terminal evidence. Human-only and otherwise restricted activities remain pending or excluded as their governing guidance requires.

## Before the loop

The pre-loop research agent must use the repository's Python plan helpers to inspect the active story and task completion. If any task is open, do not append a task. If Python confirms every existing task is complete, append exactly one fresh final validation task for this proof invocation, after the substantive tasks, using `$CODEINFO_ROOT/codeinfo_markdown/shared/final-task-creation.md` and repository-discovered scope and commands. Preserve all prior plan/proof history. The new task is the unique current closeout owner; its title or notes must identify this invocation. Within this same invocation, re-entry must recognize that owner and must not append again. A later proof invocation that again finds all tasks complete creates its own fresh owner. This explicitly overrides the prior no-new-task rule and shared closeout-owner rules only for this flow.

The final task must follow the shared shape: use the required repair-scope notes, exact repository/story scope, discovered supported lint and formatting subtasks, and the applicable supported full build, runtime/setup, full automated suites, shutdown, lint, and formatting checks in required order. Include no invented commands or unsupported checks. Preserve earlier validation tasks and evidence. Keep bounded, plan-grounded `Manual Testing Guidance` for overall story acceptance, including responsive UI menu alignment, visibility, usability, and resizing where applicable, plus human-only, excluded, or otherwise restricted surfaces. Do not make manual proof an automated testing checkbox.

The research agent coordinates one authorized plan writer. It prepares the invocation and delegates plan documentation/task changes to that writer; no other worker edits the plan concurrently. The research agent does not implement code or execute tests.

## Per-task research and automated proof loop

At the top of every loop iteration, use Python task-completion helpers as the sole break condition: exit only when they confirm all tasks complete. Do not use manual proof, an agent report, or a prior status as a loop break condition. After resetting the per-task research agent, use existing Python helpers to bind/select one task for this iteration. If no task is selected, make no task changes and stop this iteration. Selection is for work only; it must not itself mark completion.

Tell the per-task research agent to use best judgment to delegate implementation, investigation, repairs, and automated testing to appropriate subagents. Do not prescribe worker names or role-to-worker mappings. The research agent must not perform implementation or test execution itself. Implement all subtasks first. Gather terminal results from delegated work and address each individual failure through its owner. Once individual failures pass, run each affected required full suite once for that repaired candidate. If a full-suite rerun finds a new actionable failure, return to targeted diagnosis and repair; attempt the next full-suite run only after those individual failures pass, once for the newly repaired candidate. Follow the repository's wrapper, heartbeat, log, and bounded command-recovery guidance for a nonreturning command, using only recovery within the assigned owner's authority. Do not make speculative changes, repeat an unchanged failure, or retry without material evidence. Keep blocked or cancelled proof open; do not mark it complete.

Narrow monitoring exception: while awaiting a delegated worker's original terminal result, if it remains pending after 20 minutes, the research agent may make a read-only check of that worker's available, verified status, heartbeat, or owned log progress, at most once every 20 minutes per worker. Silence alone does not establish a stall; preserve the worker's ownership and cancellation rules and await its terminal result.

Use the same research-agent conversation to reconcile task checkboxes and status from terminal evidence, then report work performed, checks and results, issues and resolutions, and whether the task is complete or incomplete. It must not select another task during reconciliation. Serialize plan writes and preserve the final task's closeout ownership and prior proof history.

## Whole-story manual acceptance

At the end of the same loop iteration, after the research agent's reconciliation report, if and only if Python confirms all tasks are complete, directly run the manual testing agent in this flow. The manual tester evaluates applicable overall story acceptance against the canonical plan and repository evidence, including the bounded guidance above. It verifies the candidate and uses only the applicable authorized runtime and ownership scope. It must not make unauthorized source or test changes. Report partial, unavailable, human-only, and restricted surfaces honestly; inconclusive proof does not establish a pass and does not justify unsupported work. Manual testing is not a loop break condition. The next iteration's top-of-loop Python task-completion check exits on task completion alone.

If the tester finds an actionable story issue, it records the finding against the exact candidate and reopens the same final task to `__in_progress__`. It preserves prior proof history, unchecks every `Testing` checkbox, and adds repair subtasks plus appropriate regression-test subtasks. These plan edits and this status override are explicitly authorized only for this flow. The next iteration returns to the top: the research agent delegates implementation, then automated proof and affected retests proceed under the loop rules. Revalidate affected manual surfaces after repairs. A clean manual pass leaves the tasks complete; the next top-of-loop Python check exits. Manual inability or inconclusive evidence must be reported without inventing tasks or blockers and is never itself a top-of-loop break condition.

Stop when the Python completion check exits the loop and the final manual pass is complete or its genuine limitation is accurately reported. Preserve human proof requirements, verified candidate attribution, safe independent work, repository runtime rules, and the caller's no-commit/no-push boundary.
